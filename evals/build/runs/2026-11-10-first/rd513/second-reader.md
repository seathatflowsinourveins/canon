## Findings
1. src/canon_trading/backtest.py:227 with src/canon_trading/ledger.py:508. The digest and session days now come from `Cache.bars`, but the engine is built with `BacktestEngineConfig(logging=logging)`, so the cache keeps upstream's default `CacheConfig.bar_capacity`, which is 10000 (checked in this tree's .venv: `CacheConfig().bar_capacity` prints 10000). Any bar type with more than 10,000 bars in the sample now fails every trial: about two weeks of Alpaca 1-minute bars with extended hours, about 2.5 years of hourly bars, about 40 years of daily bars. `bars_to_catalog` loads MINUTE and HOUR bars, and `record_trial` accepts any bar type. I showed it with a scratch test (removed afterwards): 10,050 daily AAPL bars from 1985-01-07 and one `record_trial`. With the patch the trial is told FAIL ("the engine's cache holds 10000 bars and the run replayed 10050 ..."). With the source diff reverse-applied, the same input records `traded` with 10050 iterations. The failure is loud, and the README, ADR 0041 and the report all disclose it, so this is not rule 5. The repository's own study (daily bars, 2020-07-27 to 2026-01-01, about 1,370 bars per symbol) is under the cap. The case statement also asks that unaccounted bars be told failed. It is still a regression a review would send back: size `CacheConfig(bar_capacity=...)` in `backtest_run_config` to the run, so the cache can account for an ordinary sample. One could argue it is blocker 4 (an input that worked now fails). I count it as a fix because the change refuses those inputs openly instead of recording a wrong digest for them. (severity: fix)
2. change.patch file list, `.pytest-tmp/**`. The patch carries test artifacts: SQLite ledgers, `.lock` files, parquet catalogs and pytest's `*current` symlinks. They are not applied to tree2, and `.gitignore` names only `.pytest_cache/`, so a `git add -A` would commit them. Not blocker 1: pyproject.toml, tests/conftest.py and scripts/ci set no `basetemp` and nothing reads `.pytest-tmp`. Every test uses `tmp_path`, so these files do not change what a test run means. They must still be dropped from the change before landing. (severity: fix)
3. docs/adr/0041-trial-ledger-sample-and-data-identity.md:156,163. The new Evidence bullets are written from the task's side ("Defect repair", "The supplied regressions ..."), not for a later reader as the repository's record style asks. Reword them as the evidence that was read, and drop the framing of a task. (severity: fix)
## Per-defect check
1. Digest and session days read from the catalog after replay: removed. `ledger.bars_read` is gone, `BacktestRun.bars` is captured from `cache.bars` before disposal (backtest.py ~291-300), and `record_trial` checks the count against `iterations`, bars outside the sample and bar types not requested before it writes any result (ledger.py 507-522). Ordering per bar type matches the old `bars_read` order, so ADR 0041's bytes are unchanged. The limit is finding 1.
2. Any overlap accepted: removed. With both bounds given, `get_missing_intervals_for_request` refuses every gap and names it before `Study.ask` (backtest.py 195-210). A sample the catalog does not reach is refused the same way. A hole is closed by upstream `consolidate_data` (case test passes).
3. Keyed failure before its sample write left out: removed. ranking.py ~187-201 keeps a keyed record with no valid sample number on the current sample until a later run resolves it. A record that ran with a missing, non-int, bool or unknown sample number stops the ranking, named. variant_study `_to_record` follows the same rule.
4. Interrupted creation unrecoverable: removed. Under the exclusive lock, `create_ledger_study` loads and completes only an empty maximising study with no attributes (ledger.py 196-204, `_creation_incomplete`). `open_study` refuses it and says how to complete it. Other duplicates still raise (worker test covers trials, attributes, malformed sample, direction).
5. Session day with no return dropped: removed. `daily_series` refuses session days missing from the returns before it drops closed days (returns_matrix.py 97-104), and ranking adds the trial number.
