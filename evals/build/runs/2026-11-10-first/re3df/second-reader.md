## Findings
1. src/canon_trading/backtest.py:290-295 with src/canon_trading/ledger.py:517 — `run_backtest_config` builds `BacktestRun.bars` from `cache.bars(bar_type)`. The run config sets no `CacheConfig` (backtest.py:226 `BacktestEngineConfig(logging=logging)`), and NautilusTrader 2.0.0rc8's default `CacheConfig()` prints `bar_capacity: 10000`. The cache is a capped buffer, not a record of every bar the run read. `record_trial` then checks `len(bars) != result.iterations` and raises. So any sample with more than 10,000 bars of a bar type gets `FAIL`/`failed` on every trial, and the gate can never rank it. `bars_to_catalog` loads MINUTE bars, and 10,000 minute bars is about 26 regular-hours sessions or about 10 extended-hours days, so a study over a few weeks of minute bars can no longer be recorded. Before the change those runs were recorded. Evidence: a scratch test (since removed) wrote 10,050 daily AAPL bars from 1985-01-07 and called `record_trial` over the sample 1985-01-07..2023-07-16. With the patch: `RuntimeError: the engine's cache holds 10000 bars and the run replayed 10050` (trial told failed). On the unpatched source, same test: recorded, outcome `traded`, `iterations=10050`. The suite never sees this because its fixtures have at most 70 bars. The report's "Anything I am unsure of" only asks whether the cache could hold *extra* bars; it never mentions the cap. (severity: blocker)
2. src/canon_trading/ledger.py:397 — `bars_read` has no callers left in src or tests (only a docstring mention at backtest.py:103). It is kept "since other code could import it", but it is now dead code, and it keeps a second path that reads the digest bars from the catalog, the very thing defect 1 removes. A review would have removed it, or at least moved the docstring reference. (severity: fix)
