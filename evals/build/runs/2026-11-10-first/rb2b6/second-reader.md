2. packages/canon-alpaca/src/canon_alpaca/execution.py:689 (with 644-645 and the open-order raise at ~705) — An open order whose ID cannot be held fails start-up with "Alpaca order <id> (AAPL) is open with invalid string for 'value', was empty". The message comes from NautilusTrader's identifier check, which `order_status_report` happens to reach implicitly. Every other reason on that path names the field ("order type X", "time in force X", "status X"). The statement asks for "a reason that names it", and the order is named, so the defect is removed. A review would still have asked for an explicit `client order ID ...` reason, for example by checking `holdable_client_order_id` before building the report and raising a labelled ValueError. ## Per-defect check
1. Cancel-all skips `PENDING_CANCEL`: removed. The `order.status == OrderStatus.PENDING_CANCEL` skip is gone from `_cancel_all_orders` (execution.py ~1118), and no other skip exists (grep: PENDING_CANCEL appears only in the status map and in `_cancel_refused`). A second cancel goes through the existing 204 and 422 paths: `_cancel_refused` generates nothing when Alpaca shows `canceled` or `pending_cancel`, and a connect timeout rejects the cancel as not sent, a valid move out of PENDING_CANCEL. The module header, docstring, README and ADR 0036 note now say the same thing.
2. Unholdable client order ID: removed. `holdable_client_order_id` (execution.py:610) catches NautilusTrader's ValueError. `_root_id` no longer builds `ClientOrderId` outside `_order_report`'s handling: it starts from a holdable own ID, stops before an unholdable ancestor, and caches only a non-None root. `_node_order_id` treats an unholdable ID as none of the node's.
   - Closed order: `order_status_report` builds the ID inside its try and returns None, so the order is skipped with a warning and the mass status goes on.
   - Open order: the same path raises with the order's id and symbol, so start-up fails by name. See finding 2 for the wording.
   - Valid replacement of an unholdable order: its own ID is the root, `renamed` is None, and it is reported under its own ID.
   - Probed: NautilusTrader also refuses an all-whitespace ID with ValueError, so the helper covers that case too. No other `ClientOrderId(<alpaca string>)` exists in the package.
