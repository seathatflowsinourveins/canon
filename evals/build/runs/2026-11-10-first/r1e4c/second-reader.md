## Findings
1. src/canon_trading/backtest.py:222 and :298, src/canon_trading/ledger.py:432 — the bars of a run are now read from the engine's cache (`Cache.bars`), and the engine is still built with upstream's default `CacheConfig` (`BacktestEngineConfig(logging=logging)`), whose `bar_capacity` is 10,000 at nautilus-trader 2.0.0rc8 (checked: `CacheConfig().bar_capacity == 10000`). Any sample with more than 10,000 bars of one bar type, which is about 26 regular sessions of 1-minute bars (MINUTE bars are a supported catalog input, `bars_to_catalog.py:63`), now has every trial replayed in full and then told FAIL by `_bars_of_run` ("the engine's cache holds 10000 bars and the run replayed N"). Before the change such a study recorded its trials, because the bars came from the catalog. I showed this with a scratch test (removed afterwards): 10,050 daily bars with a sample inside the covered range gave `RuntimeError: the engine's cache holds 10000 bars and the run replayed 10049`. The failure is loud and the report states it under "Known limits", so this is not a hidden failure or a false claim. It is still a regression a review would have fixed before landing. Upstream provides the fix: `BacktestEngineConfig(cache=CacheConfig(bar_capacity=...))`, sized to the sample, or a refusal before the replay if the sample cannot fit. I did not mark it a blocker because the repo's only study driver uses daily bars (`variant_study.py:97`, ADR 0048), and about 40 years of daily bars, well past Alpaca's history, are needed to reach the cap. A minute-bar study through `record_trial` is the input that breaks. (severity: fix)
## Per-defect check
1. Digest and session days read after the replay: removed. `record_trial` no longer queries the catalog (`bars_read` deleted). Both `session_days` and `data_digest` come from `run.bars`, which `run_backtest_config` reads from the engine cache before `node.dispose()` (backtest.py:285-298). `_bars_of_run` (ledger.py:423) checks that the bar count equals `result.iterations`, that every bar lies inside the sample and that no unexpected bar type is present; it does this inside the `try`, so a mismatch is told FAIL before any digest is written.
2. Any overlap accepted: removed. `backtest_run_config` calls upstream `get_missing_intervals_for_request` over the whole requested range and names each gap in ISO-8601, with a pointer to `consolidate_data`. A sample the catalog does not reach at all is refused, either through the `low > high` guard or because the whole range is missing. Both happen before `study.ask()`.
3. Keyed failure before `sample` was written, and a record that ran with no sample number of the study: removed. `sample_number` refuses bool, non-int and unknown values (ledger.py). In `rank`, a record that ran with no valid sample number stops the ranking and is named. A keyed record that did not run and has no sample number is counted on the current sample, so it stops the ranking until a later record of its key runs. `variant_study._to_record` treats such a record the same way, so the key is re-run.
4. Creation interrupted between name and sample: removed. `create_ledger_study` catches `DuplicatedStudyError`, loads the study and completes it only if it is a MAXIMIZE study with no attributes and no trials; otherwise it re-raises. `samples()` names the case, and the error points to `create_ledger_study`.
5. Session day with no return dropped: removed. `daily_series` now builds the series over every session day, refuses one with no return (naming the count and the first date), and refuses duplicate session days.
